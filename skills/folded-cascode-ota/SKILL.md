# Folded-Cascode OTA Skill v2.2

Use with `skills/analog-design-agent/SKILL.md`.

## 1. Specification interview

Before any `.il`, ask for input-pair type, output type, PDK, VDD/VSS, performance targets, temperature/corner, gm/ID method, L strategy, layout-oriented requirements, bias strategy, external interface, and whether VDC sources are required. Confirm the Design Contract.

## 2. Current reference contract

```text
Input pair = NMOS
PDK = tsmcN65
VDD = 1.5 V
VSS = 0 V
Single-ended output
DC Gain target > 60 dB
GBW target >= 100 MHz
CL = 5 pF
Temperature = 27 C
Corner = TT
gm/ID = Auto
L selection = gm/ID optimized
Layout-oriented = YES
```

Starting bias values are reference/engineering starting values only.

## 3. TotalW-first device sizing — mandatory

At design level every MOS is specified with:

```text
TotalW
L
NF
M
```

Verified tsmcN65 mapping:

```text
TotalW -> wf
L      -> l
NF     -> fingers + nf
M      -> simM + m
W      -> explicit per-finger implementation width
```

Every generator must explicitly assign the complete sizing state:

```skill
cdf->w->value       = W_PER_FINGER
cdf->l->value       = L
cdf->wf->value      = TOTAL_W
cdf->fingers->value = NF
cdf->simM->value    = M
cdf->nf->value      = NF
cdf->m->value       = M
```

Print and validate all fields. `wf` is the authoritative TotalW field. New generators must not expose W-first sizing to the user.

## 5. Topology reference


Single-ended output is on the right branch.

## 6. Terminal routing — mandatory

Each S/G/D/B is independent:
```text
terminal -> short straight stub -> net label
```

Never physically connect terminals solely because they share a logical net. No diagonal, looping, through-body, overlapping, touching, or standalone decorative wires.

For actual terminal direction use transformed pin coordinates and derive axes from terminal pairs:
```text
G = G - B
B = B - G
S = S - D
D = D - S
```

## 7. PMOS source-top rule

Every PMOS that must be source-top/drain-bottom is verified from actual transformed S/D coordinates. Require `S.Y > D.Y`. Do not hard-code `MY` for another PDK.

## 8. External pins and VDC-driven nets

Use `basic/iopin/symbol` + `schCreatePin` only for intentional user-facing ports. If a net is generated by an `analogLib/vdc` source, do not also create a redundant external pin by default.

## 9. Verified analogLib/vdc workflow

```text
Library = analogLib
Cell = vdc
PLUS center = (0.0, 0.0)
MINUS center = (0.0, -0.375)
```

Set source voltage through instance CDF `vdc`. Use local labeled stubs. For an explicit VSS reference source, use 0 V and VSS labels on both terminals.

## 10. Verified APIs

```skill
geGetEditCellView()
dbOpenCellViewByType()
dbCreateInst()
cdfGetInstCDF()
dbFindTermByName()
centerBox()
dbTransformPoint()
schCreateWire()
schCreateWireLabel()
schCreatePin()
```

Never use `schCreateLabel`, `hiGetString`, `gets`, C-style `(pinName == "G")`, or vector point addition `p + list(dx dy)`.

## 11. Validation gate

Before delivery confirm:
- topology/device count
- masters and TotalW/L/NF/M
- explicit W/L/WF/fingers/simM/nf/m assignment
- `wf` equals requested TotalW
- every S/G/D/B has a labeled net
- actual PMOS S/D geometry passes source-top requirement
- G/B and S/D are opposite directions
- no unintended terminal-to-terminal physical connection
- no looping/diagonal/overlapping stubs
- no standalone internal wires
- only intentional external pins exist
- VDC sources use instance CDF `vdc`
- VDC-driven nets have no redundant pins
- explicit VSS source, if used, is 0 V with VSS on both terminals
- Check and Save has no errors

Do not claim target gain/GBW until actual Cadence simulations verify them.
